## English

### Overview

Reqlyst helps developers understand which HTTP(S) requests a browser tab makes without switching to a larger debugging tool. It captures network activity through a Chrome Manifest V3 background service worker and presents a compact, searchable request list in the extension popup.

This repository was modernized from an Angular 16 prototype to **Angular 22**. The current implementation uses the **Manifest V3**, **Angular standalone components and signals**, and automated **Chromium end-to-end testing with Playwright**.

It is intended for front-end developers, API developers, testers and anyone who needs a fast overview of network activity while working with a website.

### Available features

- **Background collection:** Chrome's `webRequest` listeners collect HTTP(S) metadata while the popup is closed.
- **Per-tab inspection:** The popup displays requests associated with the active HTTP(S) tab.
- **Request details:** Inspect sanitized URL, HTTP method, resource type, tab, initiator, HTTP status code, elapsed time and network error when available.
- **Live UI updates:** Changes to session storage update the visible list.
- **Pause/resume:** Recording can be disabled or re-enabled across the extension.
- **Clear history:** Delete captured records for the selected tab without changing other tabs.
- **Bounded session history:** Up to 200 records per tab and up to 12 tracked tabs.
- **Search:** Case-insensitive text search across URL, method, resource type, request status and HTTP status code.
- **Advanced filters (v2.1):**
  - Filter by an exact hostname or its subdomains, such as `example.com` or `*.example.com`.
  - Filter by HTTP method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `HEAD`).
  - Filter by status class (`1xx`–`5xx`), pending requests, network failures, or combined HTTP/network errors.
  - Filter by resource type using values observed during capture.
  - Optionally enable regular-expression search (case-insensitive).
  - Combine filters, see the filtered/total count, and reset them all with one button.
  - Receive validation feedback for invalid or excessively long regex expressions (256-character limit).

**Important:** This tool inspects *request metadata*. It is **not** an HTTP proxy, an API client, a request replayer, a response-body viewer or a traffic modification tool.

### How to install from source

**Requirements:** Node.js meeting the repository's `package.json` engine requirement (Node 26 is used in CI), npm, and a Chromium-based browser with support for Chrome Manifest V3 extensions.

```bash
git clone https://github.com/mehrdadbahrainy/chrome-extension-web-requests.git
cd chrome-extension-web-requests
npm install
npm run build
node scripts/verify-build.mjs
```

Then:

1. Open `chrome://extensions` in Chrome.
2. Enable **Developer mode**.
3. Choose **Load unpacked**.
4. Select the `dist/chrome-extension` directory generated by the build.
5. Open a regular HTTP(S) website and click the extension icon.
6. Refresh the page or perform an API action to generate network traffic.

You can also download the unpacked extension build from the **Artifacts** section of a successful [GitHub Actions workflow](https://github.com/mehrdadbahrainy/chrome-extension-web-requests/actions), extract it, and load the extracted directory with **Load unpacked**.

### How to use Advanced Filters

All filters are applied together to the current tab's captured history. They affect the view only: filtering **does not delete recorded requests**.

| Control | Example | Effect |
| --- | --- | --- |
| Search | `/api/orders` | Find matching URLs and other metadata |
| Regex | `/api/(orders|products)$` | Match either endpoint suffix when Regex is checked |
| Domain | `example.com` | Include `example.com` and its subdomains |
| Method | `POST` | Show only POST requests |
| Status | `4xx` | Show client-error HTTP responses |
| Status | `5xx` | Show server-error HTTP responses |
| Status | `Errors (4xx/5xx + network)` | Include HTTP failures and network errors |
| Type | `xmlhttprequest` | Limit results to a recorded resource type |
| Reset | — | Restore the unfiltered view |

**Example workflow:** Open the extension, type `example.com` in Domain, choose `Errors (4xx/5xx + network)`, and search for `/api/`. The results show matching error requests from that domain, subject to what the extension has already captured.

### Architecture

| Path | Responsibility |
| --- | --- |
| `src/manifest.json` | Extension identity, permissions, popup and service-worker configuration |
| `src/background.js` | Network event listeners, serialized updates, message handling and session storage |
| `src/request-utils.js` | Creating/finalizing request records and sanitizing URLs |
| `src/request-filters.js` | Pure, composable advanced-filter logic |
| `src/request-filters.d.ts` | TypeScript declarations for the filter module |
| `src/app/app.component.*` | Standalone Angular popup, controls, results and details |
| `tests/unit/` | Node.js unit tests |
| `tests/e2e/` | End-to-end scenarios with a local HTTP fixture and real Chromium extension |
| `.github/workflows/ci.yml` | Build verification, automated tests and extension artifact |

**Capture flow:** Chrome network event → background service worker → normalized and sanitized request record → `chrome.storage.session` → popup view.

The recording preference is stored in `chrome.storage.local`. Request history is stored in `chrome.storage.session` and is not intended as permanent storage. Records for a tab are removed when that tab is closed.

### Privacy and permissions

- `webRequest` observes network request metadata.
- `tabs` identifies the tab being inspected.
- `storage` stores a recording preference and session-scoped request history.
- `host_permissions` includes HTTP and HTTPS sites because cross-site network observation requires host access.
- Common credential-like query-string fields and URL-embedded credentials are redacted before recording.
- Request/response bodies, cookies, and request/response headers are **not collected** by the current implementation.
- No analytics, account, cloud upload or external telemetry service is implemented.

**Privacy limitation:** URL redaction covers a predefined list of commonly sensitive parameter names, not every possible application-specific secret. Do not treat captured URLs as guaranteed free of confidential information.

### Development and tests

```bash
npm install
npm run test:unit
npm run build
node scripts/verify-build.mjs
npx playwright install --with-deps --no-shell chromium
npm run test:e2e
```

Or, after installing the Playwright browser dependencies, run:

```bash
npm run check
```

Unit tests verify URL sanitization, request lifecycle and advanced-filter behavior. End-to-end tests launch the unpacked extension inside Chromium, make actual HTTP requests against a local fixture, and verify the interface, status codes, filtering, recording controls and clearing history.

GitHub Actions executes the tests and build on pull requests targeting `main` and on configured push branches. On success, it publishes a build artifact for manual installation. Successful CI shows the tested scenarios passed, not that every possible browser/network situation has been validated.

### Known limitations

- Only HTTP(S) metadata for supported tabs and accessible hosts is observed.
- No request bodies, response bodies, headers, cookies or HAR export.
- No request replay, response mocking, redirection or modification.
- Filtering applies to the bounded captured history, not a full-browser persistent archive.
- Not all browser-internal pages, incognito requests, or protected traffic can be inspected.
- Regular expressions are user-provided. Use reasonably small patterns for responsive filtering.
- Chrome and extension permissions may change the set of observable network events.

## فارسی

### معرفی پروژه

**Reqlyst** یک افزونه سبک برای مرورگر کروم است که به توسعه‌دهندگان امکان می‌دهد درخواست‌های HTTP و HTTPS مربوط به تب فعال را بررسی کنند. این افزونه اطلاعات درخواست‌های شبکه را در پس‌زمینه ثبت می‌کند و در یک پنجره ساده و قابل جست‌وجو نمایش می‌دهد.

پروژه از نسخه اولیه Angular 16 به **Angular 22** ارتقا یافته و از **Chrome Manifest V3**، کامپوننت‌های مستقل و Signalهای انگولار و تست‌های **Playwright** در مرورگر Chromium استفاده می‌کند.

این ابزار برای توسعه‌دهندگان فرانت‌اند، توسعه‌دهندگان API، تست‌کنندگان نرم‌افزار و افرادی مناسب است که می‌خواهند هنگام کار با یک سایت، درخواست‌های شبکه را سریع بررسی کنند.

### امکانات فعلی

- **ثبت درخواست‌ها در پس‌زمینه:** ثبت اطلاعات درخواست‌ها از طریق Service Worker حتی زمانی که پنجره افزونه بسته است.
- **نمایش اطلاعات تب فعال:** تفکیک درخواست‌ها بر اساس تب مرورگر.
- **جزئیات درخواست:** نمایش آدرس پاک‌سازی‌شده، متد HTTP، نوع منبع، شناسه تب، منشا درخواست، کد وضعیت پاسخ، مدت زمان و خطای شبکه در صورت وجود.
- **به‌روزرسانی زنده:** با تغییر داده‌های Session Storage، فهرست درخواست‌ها هم به‌روز می‌شود.
- **توقف و ادامه ضبط:** فعال یا غیرفعال کردن ثبت درخواست‌ها برای کل افزونه.
- **پاک‌سازی تاریخچه:** حذف درخواست‌های ثبت‌شده تب انتخاب‌شده بدون حذف اطلاعات تب‌های دیگر.
- **محدودیت نگهداری:** حداکثر ۲۰۰ درخواست برای هر تب و حداکثر ۱۲ تب.
- **جست‌وجوی متنی:** جست‌وجو در URL، متد، نوع درخواست و وضعیت با نادیده گرفتن تفاوت حروف کوچک و بزرگ.
- **فیلترهای پیشرفته نسخه ۲.۱:**
  - انتخاب دامنه اصلی و زیردامنه‌های آن مانند `example.com`.
  - فیلتر بر اساس متدهای HTTP مانند `GET` و `POST`.
  - فیلتر کدهای وضعیت `1xx` تا `5xx`، درخواست‌های در حال انتظار و خطاهای شبکه.
  - نمایش یکپارچه خطاهای HTTP و خطاهای شبکه.
  - فیلتر بر اساس نوع درخواست‌های مشاهده‌شده.
  - جست‌وجوی Regex با امکان فعال و غیرفعال کردن.
  - ترکیب چند فیلتر، مشاهده تعداد نتایج و بازنشانی همه فیلترها.
  - نمایش خطا برای عبارت Regex نامعتبر یا طولانی‌تر از ۲۵۶ کاراکتر.

**توجه:** این افزونه برای مشاهده اطلاعات درخواست‌های شبکه است. قابلیت Proxy، اجرای درخواست مانند Postman، مشاهده بدنه پاسخ، اجرای مجدد درخواست یا تغییر ترافیک را ندارد.

### راهنمای فیلترهای پیشرفته

همه فیلترها به‌صورت همزمان روی اطلاعات ثبت‌شده تب فعال اعمال می‌شوند. فیلترکردن داده‌ها را حذف نمی‌کند و فقط نتیجه نمایش را تغییر می‌دهد.

| گزینه | نمونه | کاربرد |
| --- | --- | --- |
| Search | `/api/orders` | پیدا کردن درخواست‌های مرتبط |
| Regex | `/api/(orders|products)$` | جست‌وجو با الگوی منظم |
| Domain | `example.com` | محدود کردن نمایش به دامنه و زیردامنه‌ها |
| Method | `POST` | نمایش درخواست‌های POST |
| Status | `4xx` | نمایش خطاهای سمت کلاینت |
| Status | `5xx` | نمایش خطاهای سمت سرور |
| Errors | `4xx/5xx + network` | نمایش خطاهای HTTP و شبکه |
| Type | `xmlhttprequest` | فیلتر بر اساس نوع منبع |
| Reset | — | بازگرداندن فیلترها به حالت اولیه |

**مثال:** اگر در حال بررسی یک سرویس هستید، دامنه آن را در قسمت Domain وارد کنید، وضعیت Errors را انتخاب کنید و در Search عبارت `/api/` را بنویسید. افزونه درخواست‌های خطادار مرتبط با همان دامنه را از بین اطلاعات ثبت‌شده نمایش می‌دهد.

### معماری و ساختار پروژه

| مسیر | مسئولیت |
| --- | --- |
| `src/manifest.json` | تعریف افزونه، سطح دسترسی‌ها، Popup و Service Worker |
| `src/background.js` | دریافت رویدادهای شبکه، مدیریت درخواست‌ها و ذخیره موقت |
| `src/request-utils.js` | ساخت و تکمیل اطلاعات درخواست و پاک‌سازی URL |
| `src/request-filters.js` | منطق مستقل فیلترهای پیشرفته |
| `src/request-filters.d.ts` | تعریف نوع‌های TypeScript برای فیلترها |
| `src/app/app.component.*` | رابط Angular برای نمایش، جست‌وجو و جزئیات درخواست‌ها |
| `tests/unit/` | تست‌های واحد |
| `tests/e2e/` | تست‌های واقعی افزونه در Chromium |
| `.github/workflows/ci.yml` | Build، اجرای تست‌ها و تولید خروجی افزونه |

**جریان داده:** رویداد شبکه مرورگر ← Service Worker ← آماده‌سازی و پاک‌سازی اطلاعات درخواست ← `chrome.storage.session` ← رابط کاربری افزونه.

وضعیت فعال یا متوقف بودن ضبط در `chrome.storage.local` نگهداری می‌شود. اطلاعات درخواست‌ها در `chrome.storage.session` قرار می‌گیرد و برای نگهداری دائمی طراحی نشده است. با بسته شدن تب، تاریخچه مربوط به آن تب پاک می‌شود.

### امنیت و حریم خصوصی

افزونه برای مشاهده اطلاعات درخواست‌ها از دسترسی `webRequest`، برای شناسایی تب از `tabs` و برای ذخیره تنظیمات و اطلاعات موقت از `storage` استفاده می‌کند. دسترسی به سایت‌های HTTP و HTTPS برای مشاهده درخواست‌های آن‌ها لازم است.

نام کاربری و رمز عبور موجود در URL و مقدار برخی پارامترهای متداول حساس مانند توکن‌ها قبل از ثبت، مخفی می‌شوند. **بدنه درخواست و پاسخ، کوکی‌ها و هدرها در نسخه فعلی جمع‌آوری نمی‌شوند.** همچنین در پیاده‌سازی فعلی سرویس تحلیل رفتار، حساب کاربری یا ارسال اطلاعات به سرور خارجی وجود ندارد.

**محدودیت امنیتی:** پاک‌سازی URL بر اساس نام پارامترهای حساس شناخته‌شده انجام می‌شود و ممکن است اطلاعات محرمانه‌ای که در پارامترهای اختصاصی سایت قرار دارند شناسایی نشوند. بنابراین هنگام اشتراک اطلاعات درخواست‌ها باید احتیاط کرد.
